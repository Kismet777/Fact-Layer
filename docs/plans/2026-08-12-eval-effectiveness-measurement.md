## 0. 这份文档为什么存在（一条必须记住的教训）

它起因于一次自我证伪：曾用 `fl_ratio`（FL 来源占比）高来论证"FL 有效"。**这是错的**——
`fl_ratio` 只是"FL 被碰了多少次"的**相关**统计，它无法区分下面三种截然不同的情况，
因此**不能**当有效性证据。凡以聚合计数推"有效"，都是逻辑跳跃，本文的存在就是为了不再犯。

---

## 1. 先厘清"有效"的两个层次（否则测量设计整个错）

| 层次 | 定义 | 现存最强手段 | 能不能只靠日志得到 |
|---|---|---|---|
| **观测（observational）** | FL 返回的事实，**有没有被正确采纳** | LLM 读链路判定 | 能（读现存日志即可） |
| **因果（causal / 反事实）** | **把 FL 拿掉，agent 会不会变差**（更慢/更错/更返工） | 消融实验（干预） | **不能**——所有现存链路都是"有 FL"下跑的，没有对照 |

> 这与项目的 holdout 铁律同构：催收员能力要无偏估计必须 random dispatch；
> FL 的**因果**效果同理，必须有"抽掉/污染 FL"的对照组，读日志读得再狠也到不了因果。

---

## 2. 消费模式三分 A / B / C（观测层的分类）

一次 FL 读，落在三类之一：

- **A 消费并有用**：查 FL 拿到事实 → 直接用了。（唯一算正效）
- **B 消费但白用**：查 FL → 没拿到/不信 → 又去 bash/读源重取同一信息。（**负效**：计数 +1，实际白绕）
- **C 自我维护**：读 FL 是为了**写 FL**（读-改前的 slot 存在性/类型核对、覆盖审计、export 当背景）。（与"知识供给有效"无关，是 FL 管自己）

**判定 A/B/C 只能靠 LLM 读证据 + 读推理文本，不能用 regex 代理。** 已两次栽在代理启发式上：
① 把 audit 的 `no such slot` 照字面当悬空边，实为空 stub；② 用"路径指向别项目"启发式，
把 42 条 cwd=本项目的合法 trace 误判为外项目。第三次同型：**"fl 读后又 grep DDL"被启发式判成 B，
但地面真相是"核源→把正确枚举写回 FL"（健康验证）**。区分"验证 FL"与"FL 失效回退"的信号，
**只在推理文本里**，regex 在原理上够不着——不是调参能救。

## 4. 为什么因果只在"短程 + 有界 + oracle"可做（三堵墙）

三个独立的约束，**各自**都把"能干净测因果"的区域逼到同一格：

| 墙 | 在自由式长程主线上为何砸 | 何时消失 |
|---|---|---|
| **方差墙** | 多轮 agent 轨迹内在方差随 horizon 累积/发散；**两个同条件（都无 FL）臂几轮后就差很大**，FL 效应淹在噪声地板下，样本量只收窄置信区间、救不了信噪比 | **短 horizon**（单 turn 时方差还没涨起来） |
| **干净对照** | FL 事实早泄进 CLAUDE.md / MEMORY.md / 前几轮上下文，"无 FL 臂"其实偷带知识 → 低估 FL | **构造任务**（能保证无 FL 臂真无知识） |
| **oracle 缺失** | 开放式产出无标准答案，只能 LLM judge，且长发散轨迹的 judge 不可靠 | **有界任务**（答案可判；或 short-horizon 使 pairwise judge 可靠） |

**关键推论**：`T3-turn` 之所以成立，正是因为 horizon≈1 时方差墙未起、清晰 prompt 收窄输出、单步使 pairwise judge 可靠——它**合法地落在方差墙之下**，不被长程结论牵连。之前"长程测不了"外推到"turn 也测不了"是以偏概全，已纠正。

## 5. 评价单元的层级（别互相冒充、别外推）

```
read  <  turn  <  session 边界  <  整会话
 │        │           │              │
 │        │           │              └ 累积价值（不可测：方差墙）
 │        │           └ 持久/跨会话价值（T3-session；FL 主戏）
 │        └ 会话内边际价值（T3-turn；真活因果最可做的一格）
 └ 单次读的 A/B/C（T2 观测的原子）
```

- read 级 A/B/C **不能相加成任务级有效**：FL 用 10 次但任务错了，或只用 1 次却定成败。
- turn 级率**只对"被你选中那类 turn"成立**，不可外推成 "FL 全局价值"。
- 持久价值只有 session 边界单元测得到；turn-fork（两臂已在中途）看不见它。

---

## 6. 核心张力：生态效度 ⟂ 因果可测性

- **真实主线任务**：你真正 care 的活，但因果**测不干净**（方差 + 污染 + 无 oracle 三杀）→ 这里只能做 **T2 观测**（其天花板）。
- **构造 / loop 任务**：因果**测得干净**，但它是**合成活**，不是你的真活 → **T3a**。
- 中间那块——"真实开放工作上 FL 整体价值"——**目前无便宜且可信的测法**。诚实做法：**留白并标注"已知、且难测"**，不硬凑一个数去误导决策（拿噪声改 FL 比不改更坏）。

## 7. 实施优先级（建议，非锁定，待审）

全部接在**已建的 L1 access log**（`core/access_log.py`，已按 slot 记 op）之上：

1. **T2 观测**（真活的观测天花板）：把"FL 读事件 → 证据包（查询 / 实际返回 / 下游动作 + 相关 reasoning 跨度）"抽出来送 LLM 判 A/B/C。抽取**必须含决定性 reasoning 跨度**（§3 的教训）。
2. **T3a 注入式演习**（唯一能做干净的因果格，已有雏形）：构造已知答案的题，±FL 各跑、对标准答案打分，测"事实供给准不准/省不省查"。
3. **T3-turn 配对消融**（性价比最高的因果切口，次做）：在**须现查 FL** 的真 turn 上分叉 ±FL、pairwise judge。守 §3 选 turn 纪律。
4. **T3-session 边界 / 长程**：session 边界待议；长程**明确留白**、标注不可测。

> 成本要点：T2/T3 的贵不在"跑两臂"，在 ①可靠的 outcome 度量、②干净对照。降本靠**证据抽取（缩输入）+ 候选圈定（跳无关 turn）+ 抽样估总体率 / 判全量做逐槽标签（按 trace 幂等缓存、判一次）**——而**绝不**用 regex 代理换掉 LLM 判定。

## 8. "有效"的口径（已定，2026-08-12）

**本 eval 程序里"FL 有效" ≜ T2/T3-turn 口径**：
- **T2 观测**：FL 返回的事实被**正确采纳**（非 B 白用、非 C 自维护）；
- **T3-turn 局部因果**：在须现查 FL 的 turn 上，有 FL 让**这一步更好**。

**明确不追**"整体因果口径（拿掉 FL 整体变差）"——它在真实开放长程工作上受三堵墙（§4）所限，暂判不可测；
硬做只会产出噪声。T3a（构造任务的干净因果）仍做，但定位是"事实供给准不准/省不省查"这一**受限因果**，
不外推为"FL 整体价值"。整体口径**留白并标注已知难测**（§6）。

> 影响：实施优先级（§7）据此收敛为 **T2 + T3a + T3-turn** 三者，长程/整会话消融不投入。
