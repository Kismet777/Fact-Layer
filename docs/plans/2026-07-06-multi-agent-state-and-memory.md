# FL 演进：多持久角色协作的状态底座与角色记忆

- 日期：2026-07-06
- 状态：设计讨论（对抗式评审后固化）→ 待细化实现
- 涉及：`FL-022`（并发底座）、`FL-023`（持久角色模型 + warden）、`FL-024`（角色记忆系统）、承接 `FL-021 L3`（slot 与文档式真源）
- 触发：dogfood 项目「贷后催收匹配」提出跨平台（Claude Code / Codex）、多持久角色协作的诉求；讨论收敛到 FL 本体层。

---

## 零、贯穿主线（一句话）

诉求是「跨平台管理一个项目下的多个 agent」，但拆解后本质不是**管 agent**（易逝、厂商私有、追不住），而是**管 state**（持久、可移植、任意 agent 可廉价挂载）。

> **别造 orchestrator（会被大厂 merge 掉的单厂商编排），把 FL 强化成厂商中立、本地优先、版本化、可回退、能承载文档式真源的状态底座（大厂结构性不会做的东西）。**

三轮讨论的所有「理论修改」——slot 无版本、export 无 delta、并行 agent 静默丢更新——**是同一个病**：FL 现在是**无状态、last-write-wins、无版本的快照底座**。单串行 agent 用没问题；持久多角色并行一上，立刻致命。以下三个 issue 都是这块地基的组成部分。

---

## 一、协作模型：持久角色（区别于大厂的短生命周期 subagent）

本项目的「多 agent」是**抽象、持久、长生命周期的角色**，跨 /clear、跨厂商存在；agent 只是临时挂载到角色上的执行器。

**角色 = 权限/职责边界，不是可见性边界。** 所有角色都能看到全部内容（事实空间重叠 ~90%，按可见性切分无意义）；区别在**被允许决定什么、做什么**：

| 角色 | 决策权 | 约束 |
|---|---|---|
| 架构师 | 业务逻辑决策：定架构、拆模块需求、定实现方案 | 产出即契约 |
| 实现者 | 仅代码侧优化决策 | 遵守架构师方案，不得做业务决策、不得违背/修改计划 |
| 审查者 | 独立审查：代码风险 / 逻辑漏洞 / 延迟 / 内存泄漏 | 不参与实现 |
| warden | 无 | 见 FL-023 |

**每个角色的有效产出 → 落地为真源文件 + 进 FL**（架构方案 / 代码方案 / 测试逻辑方案）。这一步是**提炼接缝（promotion seam）**：角色 session 结束时，把 canonical 部分（方案、约束、决策）固化进 FL 真源，叙事/推理留进记忆层（见 FL-024）。**能约束实现者的东西必须是真源，不能是「参考记忆」**，否则实现者无绑定契约 → 漂移 → 「实现者不做业务决策」模型崩塌。

## 二、FL-022：并发底座（P0，地基，其余全部依赖它）

持久多角色即使人工「尽量不交叉」，也必然静默失败——最坏是 FL 上的 lost-update / 基于陈旧真值行动，对一个「单一真值源」项目是最坏失败。**能分区的是代码（worktree/分支），不能分区的是共享真值层**（FL 的全部意义就是所有角色读同一份事实，写入必然汇聚于此）。所以必须在 FL 内做碰撞安全，而非在外造调度器。

四个原语：

1. **per-slot revision**：每槽位版本号 / 内容哈希 + updated。是下面三条的地基。
2. **facts_set 的 compare-and-set（乐观并发）**：「设 slot X = V，当且仅当当前版本 == 我读到的版本」，版本不符则拒绝 → agent 重读重决策。防 lost-update 的最小正确原语。写入仍统一走 `fl set`（沿用 writer 统一入口）。
3. **delta-since-revision（增量变更流）**：「自版本 R 以来哪些 slot 变了」。既解 FL-021 的 export 污染（bootstrap-once + delta），也让长跑 agent 廉价获知他人改动，不必重 export、不用旧值。
4. **dependency-aware 冲突浮现**：`dependencies.yaml` 的边（derives-from / constrains）已存在；缺的是「写入时沿边检查」——B 改的 slot 正好是 A 在途操作的上游时报警。`impact_cmd.py` 已有下游遍历基础可复用。

## 三、FL-023：warden（审查角色，P2）

**warden = 只审查、无强制回退权的纯观察者。** 发现违规只做「标记 + 记录」，交人/架构师裁决是否回退。零破坏性权力 → 误报也不会把自主推进搅成 thrash。

关键约束：

- **判其行，勿判其言**：违规判定对照 **代码 diff + FL 写入 vs 架构师契约**，而非 CoT 叙事（实现者会把业务决策包装成「代码优化」，CoT 不是可靠供词）。这要求契约是精确、canonical 的文档式真源（依赖 FL-021 L3）。
- **无状态是对的，理由要准**：warden 无长期记忆，因为它要对照的契约在 FL（canonical、现读即最新）→ 无漂移。
- **成本权衡待定**：每-turn 审（早发现、回退浅、监控贵） vs 检查点审（监控便宜、发现晚、回退深）。鉴于「不可回退操作不对 agent 开放」这一**关键安全不变量**已封顶最坏后果，检查点审可能够用。别默认每-turn。
- warden 每次判定写入具体层记忆（复用 eval 语料）：既留审计，又是评估 warden 自身准确率的数据。
- 「谁执行回退」= 干净回退依赖 FL-022 的 per-slot revision + 快照，且需定义事务单元与回退深度（违规可能 CoT 未暴露、数 turn 后才显形）。

## 四、FL-024：角色记忆系统（P1，设计已固化）

**独立于 slot 的记忆挂载，参考态、永不作为真源。** 只干两件事：① /clear 后读抽象层恢复「之前做了什么」；② 离线评估思维链是否合理。**不承担权限强制**（那是 FL-023 + 契约的事）。

核心洞察：**抽象层与具体层是同一条 append-only 事件流的两个分辨率，不是两份数据**（两份必互相漂移，正是 FL 要消灭的病）。

| | 具体层 | 抽象层 |
|---|---|---|
| 内容 | prompt 原画 + CoT + 工具调用 + 总结 | 每 (role, session) 一行「干了什么」 |
| 本质 | eval 管线的扩展（L1/L2 加 `role` 维度） | 具体层 `summary` 字段的**物化索引/投影** |
| 用途 | 离线评估、性能语料、drill-down | /clear 廉价恢复 |
| 形态 | 原始记录 | 一行一条，**禁止段落级描述** |

设计要点（对抗式评审后确认）：

1. **物化 + 增量追加**：抽象层落盘为索引，session 关闭时追加一条。**因为底层 eval append-only（只追加不改），物化索引零漂移**——这是方案成立的地基。恢复读索引（小、无 LLM pass），需细节再 drill 进具体层。样板 = 本仓库 harness 的 `MEMORY.md`（一行索引）/ 记忆文件（全文）分层。
2. **加载窗口按 token 软预算截断**：用粗估（`len//4`，同 exporter），是天花板不是精确账单；跨 tokenizer 差异忽略。
3. **窗口选择用 salience，不是 recency**：纯按新旧填窗会挤掉「旧但基础性」的条目（如 30 session 前的地基决策）。复用 `build_budgeted_context`/`_score_slot`：按（重要度 + 新旧 + 依赖入度）打分，高分优先入窗。**附带消掉了「老条目上卷成概要」的额外 LLM 动作**——旧而重要者靠分数留住，旧而次要者落窗外（仍在盘上）。
4. **窗外留 truncation 信号**：静默不载入 = 伪装成完整的失忆。恢复必带「还有 N 条更早记录未载入，可 drill-down」（照抄 exporter 的 `[truncated: N omitted]`）。
5. **保留 ≠ 加载**：过期内容**不载入但不删除**。append-only 永不删——具体层是 eval 语料，删了无法评估；抽象层是其索引，删索引 = 语料变孤儿。
6. **参考态契约结构性强制**：注入时打「参考·可能过期·真源以 FL 为准」标记（照抄 harness 的 system-reminder 模式），不靠 agent 自觉。

## 五、待办（roadmap，含优先级）

- [ ] **FL-022 并发底座（P0 · 地基）**：per-slot revision → facts_set 的 compare-and-set → delta-since-revision → 依赖冲突浮现。warden 回退、export delta、并行安全全部依赖它，先行。
- [ ] **FL-021 L3 / slot 与文档式真源（P1 · 承重墙）**：架构/代码/测试方案等文档式产出如何进 FL、与原子 slot 如何共存互指。多角色 promotion 接缝依赖它，已从「开放问题」升级为承重墙。
- [ ] **FL-024 角色记忆系统（P1 · 设计已固化，待实现）**：具体层 = eval 扩展加 `role`；抽象层 = 物化增量索引（salience 窗口 + truncation 信号）；append-only 永不删。
- [ ] **FL-023 warden（P2）**：只审查无回退；判据 = diff-vs-契约；每-turn vs 检查点成本权衡；判定写入具体层。
- [ ] **具体层冷热分层（P3 · 低 / later）**：全量 transcript 永久增长，数据量积累后才咬人；近期热存、远期归档冷存。最低优先，记账即可。
