# FL 输入控制:动态层写入准入 + 三向路由劝阻(FL-029 暂定编号)

> 状态:草案 · **从属于** [`two-layer-architecture.md`](../two-layer-architecture.md),随其 §6 未决项联动
> 目标读者:FL 维护者与接手 agent
> 范围:只做写入路径上的 AI 劝阻(路由 + 冲突),不含硬拦、不定义层本身、不修下游闭环
>
> **前提变更(被两层架构 supersede)**:本稿初版前提是「slot 是唯一真源,易变信息进入即污染」。两层架构确立后该前提失效——~~易变即污染~~ 改为:**动态/决策类事实本就该是 slot,问题不在「易变进 slot」,而在「写入未按层路由」+「冲突无声落库」**。本稿据此重述。

## 1. 需求

### 1.1 写入未按层路由 + 冲突无声落库(两层架构下重述凌乱根因)

**在两层架构下,凌乱的入口根因不是「易变污染 slot」,而是「写入没进对层」加「冲突没被拦」。** 两层架构把事实分为 **稳定层(文档)**、**动态层(slot 网)**,外加「两层都不属于」的即时信息(归 `CURRENT.md`/git)。据此,写入入口的病根重述为两条:

- **路由错位**:稳定事实被写成 slot、或即时信息(进度/测试数)被写进 FL——问题是「没进对层」,不是「污染」。
- **冲突无声**:动态层写入与已有 slot 或稳定层锚点矛盾,写入者当下未必自知;等 `fl audit` 事后发现时,错误值**可能已被下游消费**——所以冲突必须在**入口**拦。

FL 现状只有事后监控(`fl check`/`fl audit`/eval),写入路径无准入,两条都在入口无人拦。

**预期结果:** 写入入口做 AI 劝阻,判两件事——**路由**(该进哪层 / 是否该丢弃)与**冲突**(是否与已有事实矛盾)。

**业务边界(不解决什么):** 不做硬拦或强制脚本闸;**不定义层本身**(层的划分、稳定层索引、着陆点归 `two-layer-architecture.md`);不设计 slot 类型体系;不负责修复下游闭环(下游是本设计的依赖,见 6)。

## 2. 功能

### 2.1 路由劝阻(判待写内容属 稳定层 / 动态层 / 该丢弃)

**职责:** 在写 slot(动态层入口)时,判待写内容的归属层,错位则劝阻改道。

- **输入条件:** 待写值 + 目标 slot(`category.slot-id`)。
- **处理结果:** 路由判定 → {**动态**(放行)/ **稳定**(劝去文档层)/ **即时**(劝去 `CURRENT.md`·git)/ `unknown`} + 劝阻信号。
- **对外行为:** 非动态类时提示改道——如「这是稳定叙事,属文档层」「这是进度,属 `CURRENT.md`」——并要求显式确认。
- **功能边界:** 判断降级(AI 不可用/超时)时放行,标注 `unknown`,不阻断写入。

### 2.2 冲突劝阻(与 slot 网 + 稳定层索引锚点比对)

**职责:** 判待写值是否与已有动态 slot 或稳定层锚点矛盾,命中则劝阻。

- **输入条件:** 待写值 + 目标 slot + 依赖图/索引筛出的相关锚点。
- **处理结果:** 冲突判定(命中/未命中/`unknown`)+ 命中的相关 slot/锚点引用。
- **对外行为:** 命中时提示冲突对象(哪个 slot/锚点、何种矛盾),要求显式确认。
- **功能边界:** 同 2.1;冲突面 = **slot 网内部 + 着陆点所指的稳定锚点**(不再是「全 slot 依赖图」)。

### 2.3 输入原则的公开与 agent 必知

**输入原则是一等、公开的物件,任何写 FL 的 agent 必须在写入前就看见它。** 原则采「两条腿」:**自律在先**(agent 依公开原则自我路由/避冲突)、**AI 劝阻在后**(入口再兜一层)。原则若只在维护者脑中,agent 无从自律,劝阻退化为唯一防线。本小节只定位「原则须公开且必被看见」,不展开判据算法(见 3.2)。

### 2.4 劝阻可覆盖 + 与下游纠正的衔接

**劝阻可 override,安全性靠下游兜底,不靠入口独木。** AI 判断是概率性的(会误杀真事实、漏放),故入口**只劝不拦、必留覆盖通道**;被 override 或漏放的由下游 `fl check`/`fl audit`/eval 纠正。**承重假设(须显式声明):** 下游必须闭环,否则劝阻被无视 + 下游不纠,凌乱仍渗入(见 6)。

## 3. 实现

### 3.1 总体架构(准入挂 slot 写路径、复用 LLM、只劝不拦、三向路由)

**设计选择:** 写入时 AI 准入,复用 `fl audit` 的 LLM 后端与 `core.config` 角色;两条判据=路由 + 冲突。**只劝不拦、可覆盖是不可动摇的关键规则**,不得升级为硬拦。

**执行流程:**
1. 写入触发(`facts_set`/`fl set`/`fl add`)进入 hook 点。
2. 抽证据:待写值 + 目标 slot + 相关已有 slot/锚点。
3. AI 判**路由**(稳定/动态/即时)与**冲突**。
4. 动态且不冲突→放行;否则→劝阻(改道 或 要求确认)。
5. override 后写入,或改记他处;判断失败按 3.4 降级放行。

**关键依赖(区别于初版):** 路由劝阻的「稳定层/`CURRENT`」目的地、冲突劝阻的「稳定锚点」比对面,都**依赖两层架构的稳定层索引 + 着陆点先存在**。在两层落地前,本能力只能做「动态 vs 即时」的二分劝阻 + slot 网内部冲突,**无法做「slot vs 文档层」的完整路由**。

**数据/接口:** hook 点覆盖 `facts_set`(MCP)与 `fl set`/`fl add`(CLI)三个写入入口,使 agent 无论走哪条路都经同一准入点。异常降级见 3.4。

### 3.2 两条判据的口径与证据

- **路由口径**:**稳定**=架构/约定/技术栈/概览类叙事(→文档层);**即时**=进度/next-steps/changelog/测试数/运行态/一次性快照(→`CURRENT.md`·git);**动态**=决策/concern/deferral(slot 网正主,类型体系见 two-layer §6.1)。
- **冲突口径**:借依赖图/稳定层索引/`fl impact` 圈定相关锚点后比对,而非全库硬扫。
- **证据**:待写值 + 相关 slot/锚点,随判定一并回给写入者,使劝阻可解释、可复核。

### 3.3 输入原则的公开载体

**三处 agent 必经载体公开原则:** `fl export`(上下文摘要携带)、写入命令返回(劝阻随 `fl set`/`facts_set` 返回)、`CLAUDE.md`(用法规则声明原则与「两条腿」)。三者覆盖「取上下文—写入—读规则」三个必经点。

### 3.4 异常与降级

**AI 判断失败绝不阻断写入。** 不可用/超时/成本受限时放行并标注 `unknown`,沿用 FL 遥测 **best-effort** 不变量;`unknown` 与「通过」分记,使 eval 能区分「判过且放行」与「未判而放行」。

## 4. 验证

### 4.1 路由 + 冲突命中质量(不误杀、不漏放)

- **验证对象:** 路由判据(三向)、冲突判据。
- **方法:** 标注样本(已知归属层、已知冲突/相容)+ 回放真实历史写入,统计误杀与漏放,并单独看三向路由的方向准确率。
- **通过标准:** 误杀率、漏放率、路由错向率均在可接受阈内(阈值见 6),`unknown` 占比处于降级预期内。
- **停止条件:** 误杀/错向过高致 agent 普遍无视劝阻,或漏放过高使准入形同虚设,则停止放量并回 3.2 调口径。

### 4.2 原则可见性 + 下游闭环依赖

- **可见性:** 核验原则出现在 `fl export`、写入命令返回、`CLAUDE.md` 三处,agent 无需追问即可获知。
- **闭环依赖(承重):** 确认 `fl check`/`fl audit`/eval 接入例行执行(尤其 `fl check` 挂 pre-commit、与 governance-cadence 挂钩)。**下游未闭环前,本能力视为「仅提示、无兜底」,据此决定是否放量。**

## 6. 未决事项

- **依赖两层架构先落地(阻塞)**:本稿的「稳定层路由目的地」与「冲突比对锚点」依赖 two-layer 的**稳定层索引 + 着陆点 + slot 类型(decision/concern/deferral)**先成形。两层未拍板前,本能力只能做「动态 vs 即时」二分 + slot 网内部冲突,无法做完整三向路由。
- **下游闭环现状待核(阻塞)**:承重假设依赖 `fl check`/`fl audit`/eval 例行执行并接入 pre-commit / governance-cadence;未闭环前只有「前移提示」无「事后兜底」。
- **判据阈值未定**:误杀/漏放/路由错向的可接受阈值与 `unknown` 占比预期尚未标定。
- **从属地位**:two-layer 走向若变,本稿随之调整。
